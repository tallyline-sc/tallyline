## Reproducible measurement protocol

1. **Freeze the whole corpus inventory.** Independently transcribe pixels twice, adjudicate differences manually and retain unreadable/partial outcomes. Only human verification creates golden data. Freeze development, calibration and untouched final holdout by session/order and terminal; all scroll neighbours, recrops and synthetic variants stay together. Previously inspected examples remain development data; if session independence is unavailable, collect new sessions. After bounded load/schema smoke checks, run every admitted core single over the whole frozen corpus, including all 174 public captures and explicitly admitted private entries. Record missing images/LFS objects; score golden groups separately from unverified smoke. Apply [R-QA-2/3 class minima and status rules](plan/01-requirements.md#quality-assurance-qa): at least four verified captures, two terminals and forty numeric fields for a covered class; synthetic coverage never becomes real hardware coverage.
2. **Bind independent inputs and outputs.** Freeze source/capture/annotation/reference hashes, clock, geometry, field parser, vocabulary, thresholds and alignment before scoring. Run recognition-only field/card crops separately from locate/layout/full-pipeline evaluation. General VLMs start with the versioned KEY/table Markdown contract, temperature 0, seed 42, context 8192, output 3072 and four threads; specialist task prompts are separate profiles. Preserve first responses and the single truncation retry separately. First answers receive only redacted pixels and their own frozen instructions, never references, priors or another answer. Record runtime/source/features, complete model/projector/dictionary/template/preprocessor/prompt hashes, seed, context/image/output limits, placement, stop reason and run index. Keep raw first outputs immutable; changed parsing creates separate derived results. Unknown, malformed, omitted, invented and partial-card outcomes remain visible.
3. **Score each single and conservative combination.** Report raw literal/digit edit errors and exact canonical price, SCU, status, name/ID, terminal, side, section and container-set matches; never repair hidden digits or silently reinterpret units. Use every eligible field in its denominator, plus assignment and whole-card coverage. Report abstentions, false flags/corrections, silently-wrong accepted fields, error-detection recall, review burden and pairs agreeing on the same wrong value. Report classes and session counts, clustered uncertainty, and R-QA-3's optimistic zero-error upper bound. All-abstain cannot win through zero accepted errors.
4. **Replay bounded combinations.** Compare baseline + each reader, then the best different-family OCR/VLM pair and at most one useful triple, with each-reader removal and escalation-versus-always-run controls. Audit apparently confident un-escalated fields. Same-family/quantisation/backend agreement is correlated. Unevaluated combinations cannot increase sendability; contradictions stay ambiguous, independent-witness rules still bind, and USER/confirmed fields remain immutable. [Fusion contract](plan/07-ocr-concept.md#27-optional-local-ai-readers-automatic-mode-only-while-the-game-is-closed)
5. **Measure fit and lifecycle.** Separate cold load, preprocessing, vision/prefill, generation, parsing/fusion, unload and end-to-end median/p95; randomise order and perform three warm repeats on a fixed stability subset. Measure whole process-tree peak host/private/working-set and dedicated/shared VRAM, idle retention, threads, timeouts/OOM and disk; missing counters are unknown. Test cancel during load/vision/generation, shutdown/crash and game start, Pending recovery and verified resource release within the existing five-second deadline. The [llama CPU abort callback](https://github.com/ggml-org/llama.cpp/blob/v0.7.0/include/llama.h#L367) does not prove GPU cancellation: a bounded owned-worker termination path and VRAM release need acceptance. Test game coexistence without accessing game memory or injecting input.

Only the recorded strong RTX 5090/32-GiB-VRAM/approximately 96-GiB-RAM host is available. CPU-only, thread limits and 4-/8-GiB VM budgets on it are stress profiles. Physical older four-core/8-GiB CPU-only and ordinary 16-GiB PCs remain proposed test targets, not supported minima; strong-host or VM results cannot close their acceptance. [Hardware and measurement limits](local-vision-runtime-research.md#104-hardware-matrix-and-automatic-selection)
