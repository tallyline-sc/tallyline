# Dependency pins

> **Doc type:** Living reference — current. Last reviewed: 2026-11-05.

This file records what the pins in `.github/` cannot say themselves: the tag each pinned GitHub Action resolves to, the version and checksum of every CI tool that a workflow downloads or installs outside the crate dependency graph, and those of the native libraries that ship with the app without coming through Cargo. Rust crates are pinned elsewhere: in `Cargo.toml`, `Cargo.lock`, the `cargo vendor` directory and the `cargo-vet` records (S-3 to S-6). Amended 2026-10-12: the Gradle-based pins were replaced by the Cargo-based ones when the implementation language changed to Rust ([ADR-0005](adr/0005-rust-and-egui.md)).

## Rule

- Every `uses:` line in `.github/workflows/` pins an action by its full 40-character commit SHA, never by tag or branch (S-13). The line carries no version comment, because configuration files carry no comments; the table below records the tag instead.
- A pin and its row change in the same commit. A `uses:` line without a row, or a row without a `uses:` line, is drift and is fixed in the commit that notices it.
- Before a SHA is pinned or bumped, check that the tag resolves to it, for example with `git ls-remote https://github.com/<owner>/<repo> 'refs/tags/<tag>*'`. For an annotated tag, pin the commit of the peeled line (`refs/tags/<tag>^{}`), not the tag object. Record the date of the check.
- Dependabot proposes action updates by SHA weekly to the newest stable release eligible after seven days, including major upgrades (S-7, restored by the owner 2026-11-01; security updates remain exempt). The pull request updates the row; the reviewer repeats the check above.
- An action step whose default behaviour includes a proprietary component is configured to switch that component off (S-37). The "Notes" column records how.
- A CI tool that a workflow downloads is pinned by version and by the SHA-256 of the downloaded file, verified before it runs (S-13, S-19, S-36); a Python tool is installed from a hash-locked requirements file. The SHA-256 is taken from the release's own checksum file and checked against the downloaded file.
- A tool installed with Cargo (`cargo-deny`, `cargo-audit`, `cargo-vet`, `cargo-mutants`, `cargo-llvm-cov`, `cargo-packager`) is installed at an exact version with `--locked`, or downloaded as a release binary with a fixed SHA-256, and has its row below. Which of the two a tool uses is chosen and verified in M0; `cargo-deny` uses the release binary (decided 2026-10-14, issue #15: a compile from source would add minutes to every run on both systems, and the release publishes a checksum file), `cargo-audit` and OSV-Scanner use release binaries too (issue #16), and `cargo-vet` is compiled with `cargo install --locked` (decided 2026-10-14, issue #16: its release binaries stop at 0.10.0, whose parser skips audits that newer sources write, and one extra job of a few minutes is cheaper than a store the tool reads differently from the maintainer's).
- A value marked "read from source" was taken from the named tool's source code and has not yet been compared with the released asset. It is re-checked against the release asset, and the row updated, before the pin is relied on.

## Dependabot

Corrected 2026-11-01: `.github/dependabot.yml` covers the `cargo` and `github-actions` ecosystems weekly, includes direct and transitive dependencies and all semantic version levels, and explicitly sets seven release-age days (10 S-7). Exact version selections approved before the owner restored this rule remain valid within their approved limits; further decisions follow S-7. At most five pull requests per ecosystem remain open, with the maintainer as assignee and the prefixes `build(deps)` and `ci(deps)`. Dependabot never merges: nothing under `.github/` enables auto-merge, and `cargo xtask check` fails if that changes. It cannot update the tools of the table above, the Rust toolchain pin or the vendor hash list; those require the same latest-stable verification. A Dependabot pull request for a crate is red until the follow-up commits of the procedure in `supply-chain/README.md` land (10 S-8). Earlier dated pin rows retain their historical selection evidence; further version decisions follow S-7's current eligibility and review rules.
