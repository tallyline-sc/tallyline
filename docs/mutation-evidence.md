# Mutation evidence admission

> **Doc type:** Living reference — implemented guard, replacement measurements pending. Last reviewed: 2026-11-07.

A successful mutation-tool exit and its `caught` or `unviable` counters do not establish a usable score. Each completed selection needs its original cause logs as well as its exact source, selected mutant identities, baseline and outcomes. An unrelated workspace test failure invalidates the affected measurement.

`cargo xtask mutation` and `cargo xtask mutation-aggregate` check the retained logs before accepting counts for scoring. Every caught or unviable outcome must name a readable UTF-8 regular file directly below its `mutants.out/log/` directory, at most 16 MiB. Missing files, escaping paths and visible symlinks are refused. This is a local evidence boundary, not a claim of race-free access to an adversarially mutable directory.

The guard admits a caught outcome only with a named failed test and a failed test-run result. A test returning a domain error is valid evidence; a panic is not required. An unviable outcome requires a coded Rust compiler diagnostic or a contiguous rendered uncoded error block. The uncoded block requires a non-empty `error: ` headline, a positive Rust source location bound to the outcome's mutated `.rs` file, its numbered source line and a caret at the stated column. Both slash conventions are accepted. Generic error text or Cargo's compile-failure summary alone does not suffice; diagnostics quoted inside source snippets are also refused. ANSI colour sequences are removed before checking; unsupported escapes are refused.

Known independent infrastructure diagnostics invalidate either class, even when a genuine Rust diagnostic is also present: executable-file busy, exhausted disk space, linker failures including LNK1104, and missing or incompatible Rust crate artefacts. The log scanner is a conservative admission check for these known failures. It cannot establish that every possible failed test was caused by the selected mutation; suspicious failures still require source and cause review.

The exact selection, all locked workspace variant tests, successful baseline, outcome completeness, timeout rejection and frozen 100% whole-selection floor remain binding. Invalid evidence is not repaired by dropping affected mutants, calling them unviable, stitching retries into a run or changing the denominator. Retain the failed run and repeat the complete relevant selection after fixing its cause. An all-unviable whole selection has no measured score and fails.

## Empty selections

Pinned cargo-mutants 27.1.0 reports a successful diff-filtered empty selection with zero stdout bytes and exactly one of three stderr messages: `INFO No mutants to filter`, `INFO Diff changes no Rust source files` or `INFO Diff file is empty`. These are the three successful early exits in the [pinned diff-filter source](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/src/in_diff.rs), emitted before JSON listing by [the pinned entry point](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/src/main.rs). The wrapper accepts those exact normalised protocols as `[]`, retains both empty selection files and visibly skips without a baseline or score. Other empty output, malformed JSON, non-array JSON and an unsuccessful listing still fail. A valid JSON array is preserved.

The [pinned tool](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/src/lab.rs) tests only mutated packages for the baseline, then all workspace packages for variants under `--test-workspace=true`. Baseline success therefore does not establish workspace build capacity. The default serial worker reuses one copied build directory; this failure is not evidence of 281 independent target copies. The log contains no initial free-space or directory-size breakdown, so the exact space consumers remain unproved.

Mutation subprocesses set `CARGO_PROFILE_DEV_DEBUG=0`, `CARGO_PROFILE_TEST_DEBUG=0` and `CARGO_INCREMENTAL=0`, including listing and nested Cargo calls. This removes default debug information and incremental compilation storage while retaining default optimisation, debug assertions and overflow checks. [Cargo documents these profile settings and environment overrides](https://doc.rust-lang.org/cargo/reference/profiles.html); its [incremental setting](https://doc.rust-lang.org/cargo/reference/environment-variables.html#configuration-environment-variables) controls additional compiler state on disk. Ordinary checks, coverage, packaging and release commands retain their existing settings. Reduced debugger/backtrace detail and potentially longer repeated compilation are trade-offs.

The public `cargo xtask mutation` regression uses two small real Cargo probe packages and a CLI harness compiled from the actual entry point with the actual xtask library. A forwarding compiler recorder observes real rustc arguments; named probe tests verify debug assertions before recording execution, and separate `#[should_panic]` tests require the arithmetic overflow panic in each probe package. Hostile inherited debug/incremental settings remain effective for an ordinary Cargo control and are overridden for mutation, including the full-workspace probe. The fixture retains locked dependency resolution from the repository and runs offline. It neither reproduces disk exhaustion nor measures hosted capacity. The regression adds its own build/test time to workspace variants; replacement full current-source measurements must still establish disk capacity and completion within the unchanged 120-minute job limit. Exact selection, 32 round-robin shards, cause admission, evidence identities and the frozen 100% score floor remain unchanged.
