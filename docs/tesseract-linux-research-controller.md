## Data and process boundaries

The fixed Docker Desktop Linux named pipe is corroborated by local `docker-desktop` WSL kernel readback. The command ignores ambient Docker contexts, credentials and host/config variables and uses an empty exclusively owned Docker configuration. Every image invocation uses `--pull never` and the exact existing image digest. No shell, arbitrary executable, entrypoint, environment map or extra CLI config can be supplied through command arguments. Only returned 64-hex container IDs are inspected, killed, waited and removed.

Compilation has two CPUs, 4 GiB memory, zero swap, 64 PIDs, a read-only root, read-only prepared source/tool mounts and one owned writable build directory. Before any CMake execution, the fixed existing image sha256sum revalidates all 4,140 approved compiler/SDK files and eight bootstrap-tool identities from their exact approved manifests through bounded stdin. Its input identity, exit and owned-container receipt are retained. The five approved CMake configure/build/install steps use fixed argument arrays, at most two jobs and one 1800-second deadline. Models are absent from compilation. The generated compile set, original source allowlist, CMake cache, generated headers, verbose link files, every preprocessed translation unit and worker ELF are retained. Automated checks stop on graph, feature, target, compiler or dynamic-import differences. Build evidence binds every actual compile database, CMake cache, generated header, verbose link file, raw ELF report and compiler-preflight artefact; all are rehashed before review acknowledgement, synthetic execution and private execution. All 334 approved preprocessing argv/cwd records run sequentially through the same Cargo-built safe Rust helper in one model-free build container, within the unchanged total deadline and at most one compiler job. The helper rejects shell, plugin, alternate compiler and foreign output routes and is never placed in the private worker directory. Root must additionally review actual preprocessed/native reachability and link evidence against the approved source scope and acknowledge its exact digest before synthetic native execution.

Runtime uses independent frozen two-CPU 4 GiB and 8 GiB conditions, zero swap, one PID, user 65534, nice 5, no capabilities/new privileges, IPC none, network none, no devices/GPU/init/ports, no Docker logs and no writable model/worker bind or scratch directory. The child-only environment is cleared before fixed `env`/`nice` exec replacement. Stricter runtime-only zero core-dump and POSIX message-queue limits are explicit candidates for root review, with Docker and kernel readback; they expand no native scope. The public probe checks standard virtual mounts separately from read-only root/user binds and root-owned Docker metadata files. Network none may retain loopback; evidence concerns absence of an external route, not denial of every AF_INET bind.

For every nonempty runtime input, an attached start drains stdout while the stdin writer waits for an exact local returned-ID cgroup proof of the live population and all hard limits. Unknown proof releases no bytes and remains bounded by cancellation, child exit and the same wall deadline; a mismatch refuses admission. The exact owned Docker state must be running, unpaused, non-restarting and non-dead before and after the kernel snapshot; a created container remains zero-byte pending. Both running-state snapshots and the first successful kernel proof are retained separately from later resource samples. Recorded child contracts observe zero bytes on rejection and exact bytes on acceptance; public safe Rust Linux stdin fixtures exercise actual admission for both worker budgets. Only a validated bounded unscaled SDR PNG becomes canonical bottom-up BGR, zero-padded 24 bpp uncompressed BI_RGB BMP on stdin. Native code receives no host image pathname. Exact TSV stdout remains in the local private evidence directory; the CLI prints only closed progress/results. Inference stderr is an OS null handle before attach spawn. Model-free source compilation instead captures at most 16 MiB of stderr separately and stops if that bound is exceeded; it cannot capture private raster/result bytes. UTF-8, exact header, row/total size, input-bound geometry and finite confidence are validated without repairing currency, signs, separators, units or text. Output confidence is native uncalibrated evidence. There are no whitelists, priors, majority votes or reference answers in recognition.

The controller bounds concurrent stdin writing and stdout draining, cancellation and wall deadlines. It kills only the owned container and reaps its own attach process on refusal; fallback cleanup retains a separate metadata receipt. No automatic retry or silent budget increase occurs. A separate no-write safe Rust control establishes Docker-created bind-mountpoint layer metadata before comparing actual runtime filesystem changes. This is an enforced-boundary check and source review, not a syscall trace or proof that native code never attempted a denied side effect.

## Resource evidence

Read-only WSL inspection uses only the exact `/sys/fs/cgroup/docker/<returned-container-ID>` path after confirming cgroupfs, cgroup v2, an empty container cgroup parent and the corroborated local WSL kernel. Docker and WSL expose different PID namespaces, so a Docker State PID is not used as a WSL proc path. It reads population before resource limits so an unpopulated starting group remains zero-byte pending rather than being classified as a live limit mismatch. It validates that group's CPU/memory/swap/PID limits, population and own process metadata before reading `memory.peak` and `memory.events`; it does not enumerate foreign processes/groups, reset counters, use `docker exec` under the one-PID limit or substitute Docker current-memory statistics for a peak. A live `memory.peak` sample is the maximum up to that sample and a lower bound on the final whole-attempt peak. The observed local engine deletes the group after wait and before remove, so the final tail is unknown and `whole_attempt_peak_known` always remains false. Missing or short-lived groups are explicitly unknown. Exit and `OOMKilled` remain separate final container evidence. The kernel interface is described in the [cgroup v2 documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html). Limits are enforced even when peak collection is incomplete. These are worker container bounds; the existing VM, Windows controller and whole-application overhead remain outside them.

All conditions run on one physical development PC. Worker container memory/CPU cgroup budgets within the same existing VM are experimental conditions; they establish no weak-PC, GPU, final accuracy, calibrated confidence, production pool, Windows or clean-installed-product result. Public corpus verification flags and prior failed evidence remain unchanged.

## Operator sequence

Build the controller normally with `cargo build -p ocr-eval --bin tesseract-research --locked`. Freeze the checked source commit and resulting executable hash before preparing a real campaign. All later commands use that same executable, which rechecks its identity and all frozen source/input/model manifests. A changed binary requires a new campaign; do not replace prior receipts.

1. `cargo run -p ocr-eval --bin tesseract-research --locked -- probe <fresh-public-directory>` builds only the committed dependency-free safe Rust probe through Cargo, offline, with the pinned toolchain in the exact image. The public sequence also measures the model-free Build-kind container overhead and checks both actual stdin-admission fixtures. Its eight snapshot/deadline/output/OOM conditions check kernel limits, mount/permission and process/network denial, output bounds, deadlines and OOM for both budgets. It never mounts a model or private input.
2. `... -- prepare <campaign-directory> <approved-linux-v1-directory>` validates every approved/prepared/input hash and exclusively creates `controller/`, bounded BMP snapshots and separate one-model directories. No native programme executes.
3. Root alone: `... -- build <campaign-directory> <matching-public-probe-directory>`. Inspect the retained generated scope, complete preprocessed outputs, verbose link evidence and ELF report. An unexpected result is a stop, not permission to edit native sources, guess cache overrides or add tools.
4. Root alone: `... -- accept-build-review <campaign-directory> <build-evidence-sha256>`. This records the operator's actual source/reachability review of that exact evidence; it is not automatic proof of an audit.
5. Root alone: `... -- synthetic <campaign-directory> <matching-public-probe-directory>`. This invokes only public blank BMP input under each frozen native runtime condition and requires matching controller/probe/build identities. A failed public isolation or native synthetic gate blocks all private inference.
6. Root alone: `... -- run <campaign-directory>`. The fixed five panels, best/fast English models, PSM 11 and separately frozen 4/8 GiB budgets define twenty attempts. Each has exclusive start/TSV/parsed/metadata artefacts. A failed attempt preserves an incomplete campaign and stops; it does not silently rerun with a larger budget. `CANCEL` in the owned controller directory cancels the active native attempt.

`resource <recorded-metadata> <4g|8g> [recorded-inspect.json]` validates recorded own-cgroup limits/peak evidence without kernel access. `bmp <source.png> <fresh.bmp>` and `tsv <input.bmp> <recorded.tsv> <fresh-private.json>` are non-inference real-file contracts. `verify-evidence <owned-directory>` checks recorded generated-file hashes without a process; `verify-model <best|fast> <traineddata>` checks the fixed model identity without a process. `contract <deadline|output|row|blocked-stdin|error|environment|cancel|stderr|runtime-stderr>` exercises recorded own-process lifecycle fixtures. `fixture` is a fixed own-process test mode, not an arbitrary subprocess interface. The public `isolation-probe` binary is never placed beside the official private worker.
