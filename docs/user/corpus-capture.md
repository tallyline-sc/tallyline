# Corpus capture and annotation

> **Doc type:** Living reference — current. Last reviewed: 2026-11-04.

The offline `ocr-eval` tool supports R-QA-1, R-QA-3 and R-DOC-1. It inspects metadata and sample readiness before recognition is implemented. No current class is claimed to meet recognition accuracy, confidence or runtime requirements.

## Capture a reproducible ladder

1. Stand still in terminal interaction mode. Keep the FOV and scroll position fixed, move the cursor off the cards, disable hints and global chat, and keep `r_DisplayInfo` off the evaluated screen.
2. Start at 1920×1080, Windows HDR off, the SC screenshot key, the default renderer, no upscaler and default gamma/brightness/contrast. The terminal screen should fill at least 75 % of the image height. Capture both Buy and Sell at two or more terminals, including blue and orange themes.
3. Change exactly one factor per ladder. Resolution steps are 1920×1080, 2560×1440, 3840×2160, 3440×1440 and 5120×1440, plus windowed. Distance steps at 1080p are the base distance, ×1.25, ×1.5 and ×2. Record a ladder id, factor and step in `conditions.ladder`.
4. For each recommended capture method and Win+PrtScn, capture Windows HDR off, Windows HDR on/game HDR off, and both on. Use the SC screenshot key with DX11 and Vulkan while both are selectable; also capture Xbox Game Bar PNG and Snipping Tool with HDR screenshot colour correction off/on where available. For Win+PrtScn, record Windows SDR content brightness at zero and the tester's normal value. These methods are test targets, not verified recommendations yet.
5. After a graphics or HDR change, wait for a stable image (initial protocol value: at least five seconds). Finish a ladder within five minutes where possible; live stock and prices can change. Capture methods must keep the same fixed order per step.
6. Record all known per-capture conditions immediately: file/game/display resolutions, window mode, FOV, renderer/upscaler, gamma/brightness/contrast, HDR states, Ref-White, peak brightness, Windows SDR brightness, capture method/version/options, OS, channel, game version, container/transfer and source fidelity. Unknown values stay `null`.
7. Keep originals byte-identical in private storage. Redact only personal regions in the public copy: balance, player names, chat and the debug overlay's Session line. Never cover the shop panel, location field or anchors. Use filled rectangles; preserve PNG pixels and use a lossless JPEG block wipe, or decode once to PNG and record the changed fidelity. Obtain capture/publication consent before adding public images; see [corpus rules](../../corpus/README.md).

Also capture scrolling with and without overlap, long/similar names, dimmed cards, a full multi-monitor desktop and a Snipping Tool region. Optional hardware and platform ladders are listed in [R-QA-2](../plan/01-requirements.md). Do not fabricate unavailable hardware classes.

## Inspect the inputs

Run `cargo run -p ocr-eval --locked -- inspect`. An alternative public root uses `inspect --public <directory>`. Set `TALLYLINE_CORPUS_DIR` to an optional private root containing matching entry directories. Each entry's `id` must equal its directory name. The JSON report includes expected values, capture conditions, available captures, reference metadata, class sample counts and explicit skips. Redirect it only to a local file; private annotations may contain private source metadata.

An LFS pointer fails with a non-zero exit and a `git lfs pull` instruction. Missing directories, images or private checksums are visibly skipped. Inspection does not decode images: available bytes are input availability, not a successful recognition test. Every private entry needs `SHA256SUMS`, with SHA-256, two spaces and a relative filename per line. Include every private annotation, image and reference recording used; mismatches fail. Relative paths cannot escape the entry. A private directory containing only a frozen snapshot can use its matching public `expected.json`; conflicting public/private annotations fail. The same public/private capture is counted once.

Class statuses are sample readiness only: `gated` requires at least four available verified real captures from at least two known terminal IDs and forty numeric fields; `insufficient` has available real captures below those minimums, `synthetic only` has synthetic captures alone, and `missing` has no eligible capture. Numeric fields here are the non-null SCU and price values on complete cards. Unverified entries supply smoke counts, never verified numeric counts. Re-encoded captures supply only theme and measured text-band classes. Generated fixtures can identify a synthetic capture with `synthetic: "synthetic:<id>(<parameters>)"`; they never satisfy real class coverage. Compound condition rows retain combinations alongside individual dimensions. Required resolution/method/HDR/renderer/theme/band classes are seeded so missing data stays visible; detailed ladder completeness is still reviewed against R-QA-2. Accuracy, silently-wrong counts, bounds, runtime and memory are explicitly not evaluated yet.

## Measure and propose

Choose the smallest complete card and place anchors in source pixels. Create a separate JSON input such as `{"priceTop":100,"priceBottom":110,"displayHeight":1000}`. The first two anchors bound the price capital height; `displayHeight` is the display height used for its fraction. Coordinates must satisfy `0 <= priceTop < priceBottom <= displayHeight`.

Run `cargo run -p ocr-eval --locked -- annotate <expected.json> <anchors.json> <proposal.json>`. The output must not exist. The tool copies the schema-v2 entry, proposes `priceCapHeightPx`, `displayHeightFraction` and the R-QA-2 text-height band, and always sets the proposal's `verified` to `false`. It never edits `expected.json` or confirms a transcription. Review the proposal against the pixels; only a human may deliberately promote an entry to verified. Never replace expected values from recognition output.

## Freeze reference metadata

Reference inspection reads `reference/metadata.json` with `fetchedAt` (ISO 8601 with offset), `priorProvenance` (`pre-capture` or `post-capture`) and a `recordings` object mapping endpoint paths to local JSON response filenames, for example `{"/commodities_prices":"prices.json"}`. Keep response bodies in their recorded `data` envelope. Record the endpoints specified in [07 §4](../plan/07-ocr-concept.md#4-measurement-and-test-concept); incomplete metadata is not a replayable snapshot or a prior-dependent metric pass. The CLI never fetches data, reads the app cache or changes the frozen timestamp. Full DTO replay and the fixed evaluation clock belong to the recognition evaluation stage.

O-50 permits small anonymised public fixtures, restricted to this entry's terminal and commodity IDs, and forbids full price dumps. The inspector checks the endpoint allowlist, rejects known personal/secret fields and rejects public terminal/commodity/price rows outside the entry's expected IDs. This is a structural guard; human review remains responsible for anonymisation, the small-fixture limit and location-record scope. There is no invented numeric size allowance. Keep larger snapshots and originals private, hash-pin private files, and never attach them to a public issue. A post-capture snapshot is labelled separately and cannot establish prior-dependent correctness. Re-freezing is an explicit corpus change requiring a reviewed diff.
