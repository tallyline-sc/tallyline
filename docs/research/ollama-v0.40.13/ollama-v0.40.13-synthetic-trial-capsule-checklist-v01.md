# Minimal synthetic CPU trial capsule

> **Doc type:** Living reference — fields required for a concrete reviewable proposal; not a runnable trial or admission. Last reviewed: 2026-11-07.

This checklist preserves [ADR-0012](https://github.com/tallyline-sc/tallyline/blob/2ef5e31d27bcbdb986ab62ad561ba4f77df36887/docs/adr/0012-strictly-local-recognition-delivery.md) and [ADR-0013](https://github.com/tallyline-sc/tallyline/blob/2ef5e31d27bcbdb986ab62ad561ba4f77df36887/docs/adr/0013-conditional-ollama-delivery.md). The conditional Ollama policy is already authorised. These are the concrete missing evidence/command fields for the existing candidate, not a repeat policy question or a new runtime/model choice.

1. **One frozen executable closure and its evidence.** Name the existing CLI by absolute path, 40,931,208 bytes and SHA-256 `c1cca2937421d78877d5961746d25e33acd62e194d881f90fb63dca7f3e10f41`; attach the full exact 25-file candidate inventory, 83,029,576 bytes, retaining all 14 scoring variants. Attach the portable authenticity claims/proof mapping, its fresh integrity observation and all 30 official package-log matches. State the accepted provenance evidence level and unresolved cryptographic/source/build claims explicitly. Bind any additional loader/provider file actually needed before treating the closure as final.

2. **One exact research qualification.** State the native and assembler sources, build/toolchain evidence and unknowns, licences/notices, SQLite 3.53.4 CGo scope and gods/v2 alpha qualification. Existing Rust SQLite 3.54.1 and ORT exceptions do not transfer. Use the existing native review process; Tallyline-owned implementation stays Rust. Bundled versus installed CLI changes redistribution work, not execution admission or private-child ownership. Keep the separate ORT prerequisite unresolved.

3. **One existing complete profile.** Fill exact model/config/manifest and every layer, projector, template and runner identity and hash, licence, context/input limits and resource expectations. Freeze locality/cloud/forwarding classification and fail closed on unknown or changed identities. Do not populate this with a newly selected model or mutable tag. Any later acquisition has its own exact approved destinations, TLS/redirect/metadata and storage/cancellation/rollback record; this synthetic trial performs no acquisition.

4. **One concrete owned command and isolation record.** Supply the exact absolute executable, arguments and supported existing controller command. List every child-only environment value and private home/config/keys/store/cache/log/temp path under the dedicated research root; inherit no foreign runtime/store or credentials. Name a literal loopback address and unoccupied port. Specify OS proof that the listener belongs to the new app-owned child/process tree before sending input; refuse a pre-existing listener and never attach to or stop a foreign service. Record offline/forwarding refusal controls without altering global settings or widening DLL search.

5. **One bounded synthetic input and lifecycle plan.** Freeze a non-sensitive synthetic image and prompt by hash, containing no capture, reference transcription, UEX prior or other reader's answer. State CPU-only provider selection, exact thread/priority settings, actual enforced resource/time/queue bounds, expected completion limits and stop conditions. Resource knobs alone are not hard caps. Specify five-second cancellation/unloading checks, whole-process-tree release and private-state deletion/rollback, plus what happens after crash, timeout, provider failure or changed bytes.

6. **One observation record.** During the separately admitted trial, observe actual dynamic modules/providers, CPU/GPU use, OS listener ownership, all network/forwarding attempts, private writes, cancellation and full process-tree release; compare them to the frozen proposal. A static import list or loopback URL cannot establish these results. Proceed to independently prompted safe-corpus measurements only after the appropriate evidence and authorisation exist. One strong PC is the available hardware: throttling or VMs do not establish physical weak-PC support.

The [historical authenticity follow-up](ollama-v0.40.13-authenticity-follow-up-v01.md) fills part of item 1 and adds bounded build observations for item 2. Items 2–6 are not completed by a successful hash comparison. No executable synthetic command, model identity or runtime permission is invented in this checklist.
