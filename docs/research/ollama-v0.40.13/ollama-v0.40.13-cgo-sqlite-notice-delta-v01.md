## What the additional evidence establishes

- **58 declared modules are source-consistent.** Every embedded module/version/h1 agrees with the fixed [Ollama go.mod](https://github.com/ollama/ollama/blob/04088e7c9d41cba5d33bafbf788d87a465c79d5b/go.mod) and [go.sum](https://github.com/ollama/ollama/blob/04088e7c9d41cba5d33bafbf788d87a465c79d5b/go.sum); all 58 fetched `.mod` h1s were reproduced. Source revisions come from 46 observed proxy Origin records and 12 GitHub tag/commit observations. Complete source ZIP h1s were reproduced only for go-sqlite3 and gods/v2. Matching observed checksum-database text is retained; local verification of its signature and inclusion/consistency proofs remains absent.
- **The SQLite source is identified.** go-sqlite3 v1.14.52 resolves to `b0be46fa28d17ee0b65c79774ac0dad84b6db068`; its [amalgamation](https://github.com/mattn/go-sqlite3/blob/b0be46fa28d17ee0b65c79774ac0dad84b6db068/sqlite3-binding.c) identifies SQLite **3.53.4**. The complete 106-file ZIP is 2,955,060 bytes; its source/member hashes are in the delta. This differs from the approved rusqlite 0.41.1/libsqlite3-sys 0.39.1/SQLite **3.54.1** [register](../../../supply-chain/sqlite-native.json). That approval does not cover the Go wrapper, different amalgamation, compiler flags or other Ollama native/assembler scope.
- **SQLite has a CLI source explanation.** `main.go` imports `cmd`, which imports `cmd/launch`; the latter's [vscode.go](https://github.com/ollama/ollama/blob/04088e7c9d41cba5d33bafbf788d87a465c79d5b/cmd/launch/vscode.go#L16) unconditionally imports go-sqlite3 and contains an integration method that opens SQLite. GUI `app/store` is therefore not the only source explanation. Source imports and matching binary strings establish neither exact compiled source nor executed call reachability. The [CGo](https://github.com/mattn/go-sqlite3/blob/b0be46fa28d17ee0b65c79774ac0dad84b6db068/sqlite3.go#L7), [Windows](https://github.com/mattn/go-sqlite3/blob/b0be46fa28d17ee0b65c79774ac0dad84b6db068/sqlite3_windows.go), external-library and extension-omission selectors are recorded as source branches. Extension-loading API presence does not show that an extension was loaded; actual options remain unproved.
- **Trimpath prevents recovering the missing flags from this frame.** The CLI claims Go 1.26.10, CGo enabled, Windows/amd64 and trimpath. The exact [Go metadata writer](https://github.com/golang/go/blob/4e8c85f5319d999bfd7617fdc191631e5634e3c5/src/cmd/go/internal/load/pkg.go#L2423) omits CGo flag settings and linker-flag metadata under trimpath. Their absence proves neither empty/default flags nor an unchanged toolchain/SQLite build. The upstream [Windows recipe](https://github.com/ollama/ollama/blob/04088e7c9d41cba5d33bafbf788d87a465c79d5b/scripts/build_windows.ps1) describes intended inputs; it does not bind the acquired executable to exact compiler bytes and overrides.
- **61 module licence/NOTICE texts match.** These cover all 58 embedded modules after CRLF/LF and trailing packager-separator newline normalisation: two comparisons use complete h1-checked module ZIPs, 59 use fixed-commit source files, including five explicit inherited parent licences. The [notice generator](https://github.com/ollama/ollama/blob/04088e7c9d41cba5d33bafbf788d87a465c79d5b/cmake/generate_go_license.cmake#L48) collects CLI and GUI roots on Windows, explaining the 67-section superset without proving extra compiled CLI modules. gods/v2 **v2.0.0-alpha** retains its upstream prerelease qualification and complete [BSD/ISC licence](https://github.com/emirpasic/gods/blob/14f714261f50e6d3e4af1cd29e4ae11ffdedab94/LICENSE); no Tallyline exception was granted. Five [LLVM reference licence texts](https://github.com/llvm/llvm-project/tree/3b5b5c1ec4a3095ab096dd780e84d7ab81f3d7ff) do not occur in full in the four acquired notices. Actual runtime/toolchain source mapping remains unproved, so this is **not a licence-violation finding**.

Go appears because Ollama's upstream CLI is written in Go and its CGo dependency can introduce native scope. Inspecting that dependency introduces no Tallyline Go code, Go build or selected runtime. Tallyline's own-code Rust rule remains [ADR-0005 D1](../../adr/0005-rust-and-egui.md#decisions).

## Delivery route and remaining proof

The baseline remains a partial observation: **30 members, 26 PE files, four notices and 83,611,431 decompressed bytes**; the source-expanded candidate retains **25 native files, 83,029,576 bytes and all 14 CPU scoring variants**. It is not an authenticated full archive or a complete dynamic load closure. These findings narrow source/notice questions without admitting execution or redistribution.

[ADR-0013](../../adr/0013-conditional-ollama-delivery.md) already permits the conditional Ollama policy; no repeat policy question is needed. It prefers a bundled private CLI and allows user installation only when bundled delivery cannot be implemented acceptably.

| Obligation | Bundled private CLI | Selected user-installed CLI |
|---|---|---|
| Runtime execution admission | Source/native/licence/provenance/integrity review, exact executable/native/profile identity and private owned child | The same gates apply before execution. Merely calling a foreign running service is not an allowed shortcut |
| Tallyline redistribution | Exact shipped inventory, compatible terms, notices/licence texts, integrity, SBOM and applicable source duties | External runtime bytes are not redistributed by Tallyline. Do not copy its DLLs or extend ORT's search path; recheck installation/updater drift |
| Privacy and acceptance | Private home/config/keys/store/cache/log/temp roots; literal loopback with OS ownership; local-only/offline behaviour; cancellation and whole-tree resource release | The same controls and observations are required, with replacement races additionally checked |

User installation avoids packaging the external runtime; it does not supply missing runtime provenance/native evidence. A separately authenticated installed closure could replace the partial-archive candidate, but no such admitted replacement is established here. Neither route resolves the separate [ORT prerequisite](../../adr/0012-strictly-local-recognition-delivery.md#delivery-evidence-still-required) or permits Microsoft runtime redistribution.
