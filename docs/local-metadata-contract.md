# Local metadata transport contract

> **Doc type:** Living reference — source contract; operating-system ownership and runtime admission remain open. Last reviewed: 2026-11-06.

The Recognition metadata port and `adapter-vlm::api::LocalMetadataClient` provide only credential-free `GET /api/version` on literal HTTP `127.0.0.1`. They accept no URL, route, headers, body, image, prompt, model or credentials. There is no desktop composition or selected engine/profile. AI remains Off by default under R-VLM-6/7 and ADR-0013.

## Ownership and lifetime

Recognition owns immutable nonzero `MetadataGeneration`, `LoopbackConnection` ports and `MetadataAttempt`, closed session/observation/refusal enums and `MetadataOwnershipSession`. The core names no socket, HTTP, OS identity or runtime type. An attempt is an observation request, never an integrity certificate or permission to send private input. A session represents one owned generation and signals cancellation, replacement or lost ownership.

The adapter awaits reqwest's supported connector, retains its actual connection and inspects the connection's public `HttpInfo`. Both addresses must equal `127.0.0.1`, the remote port must equal the configured endpoint and the connection must not be proxied. The session observer receives that actual client/server tuple. HTTP receives that same connection only after an Owned observation matches both tuple and generation and a synchronous session-state recheck succeeds. Unknown, foreign, mismatched or stale observations close the connection without request bytes. A late Owned observation cannot reopen cancellation. Session state is also checked before connecting and before returning metadata; revocation races the entire operation and the connector separately.

Each version call constructs a private reqwest client with an operation-specific connector context. HTTP/1 is forced; proxying, redirects, retries and idle pooling are disabled. Every sequential read therefore crosses a fresh actual-connection gate. TLS construction retains the explicit AWS-LC/platform-verifier idiom without installing a global provider, including for this plain HTTP route. No TLS handshake or certificate lookup is needed for its fixed HTTP endpoint.

## Explicit bounds and outcomes

`MetadataBounds` requires a positive total duration and nonzero cumulative response-byte cap; no product defaults are chosen. One absolute deadline starts before client construction and covers connect, ownership observation, response headers and body. Synchronous construction and observer/state work cannot be pre-empted. Explicit absolute-time checks after that work prevent starting transport, releasing the connection or publishing metadata after the deadline; cooperative Tokio timeouts additionally cancel pending work. A declared oversized body is refused before waiting for its data; all received chunks are counted cumulatively before JSON parsing. The bound limits retained body bytes, not the HTTP dependency's internal transport buffers or response headers.

Only successful HTTP status and a JSON object containing exactly one nonblank, control-free version string produce `VersionMetadata`. A bounded first-token check requires object shape before the derived field parser; sequence-shaped metadata, unknown or duplicate fields, non-string values and trailing JSON are refused. JSON whitespace around the object is accepted. The result carries the observed generation and grants no runtime/profile admission. Refusals carry no response body, remote diagnostic or string error. Transport and malformed metadata are separate from ownership, generation, cancellation, total-deadline and body-size refusals.

## Public contracts and evidence limits

`crates/adapter-vlm/tests/local_metadata.rs` and its focused modules use actual ephemeral loopback listeners and the public adapter interface on current-thread Tokio runtimes. Only the ownership/session observer is fake. Contracts cover silence while held, zero-byte EOF on foreign/unknown refusal, the exact fixed credential-free GET, typed version/generation, cancellation and late decisions, wrong tuples/generations, delayed revocation notification, held-gate and shared gate/body deadlines, declared/cumulative chunk limits, sequential admission, redirects and proxy environment isolation in a bounded same-test-executable child.

The initial paired admission test had compiler RED on the absent public declarations. Behavioural RED then reproduced held-cancellation timeout, one request byte instead of EOF for mismatched observations, one byte for the delayed-notification replacement race and a stalled declared-oversize response. Each was followed by a passing focused run. A further public regression reproduced a late successful result after a deliberately long final synchronous state read; explicit post-state absolute-deadline checks close that gap. Immediate-notification replacement, the long-observation poll and the additional pending-deadline/chunk/sequential/redirect/proxy contracts were already green; those are supporting coverage, not separate RED claims.

The object-shape regression first reproduced a successful version result for `["fixture"]` over the public real-socket seam. The first-token object check then made that regression pass without replacing the strict derived field parser. Supporting missing/unknown/duplicate-field, non-string/null, blank/control-string, scalar and trailing-data refusal cases were already green on the incoming parser; the ordinary successful socket contract also covers surrounding JSON whitespace.

These observations prove transport ordering and session gates for harmless fixtures. They do not prove Windows process ownership, executable/native closure, replacement-safe OS observation, model identity, runtime execution, private-input admission, resource caps, five-second whole-process cleanup or packaged Windows/Linux acceptance. The approved Windows owner backend remains a separate implementation slice. No unsafe code, native feature, process launcher, model acquisition or general HTTP client is added here.
