# Source-compiled WiX inputs

This directory retains the reviewed source patch for the independently compiled WiX 7.0.1 MSI tool of [ADR-0011](../../docs/adr/0011-source-compiled-wix-packaging.md). It contains no executable or SDK. The patch keeps upstream notices and default EULA/Burn/native selections when its profile flags are absent; the SDK selector change is an explicit build delta. Its changes are under the MS-RL. The full text is in `LICENSES/MS-RL.txt`.

Upstream tag `v7.0.1` resolves to commit `642f1a0f7c857ffa4fc9fa3f9d1433aab895dd29`. The original [source archive](https://api.github.com/repos/wixtoolset/wix/tarball/642f1a0f7c857ffa4fc9fa3f9d1433aab895dd29) hashes to `68f85e38957f69de2b42dd039be8533a8554c249ec45bd90ed6c766664ec3795`; the patch hashes to `26df53cffb2d76ba4712fa599e85e1874c214e30abba22253cb9258f57fc688a`. The retained modified-source ZIP hashes to `ab7f6017e867018d2cffd28ef322bda01197a6d347ab043113c6e44d90d27e7c` and excludes proprietary merge-module helper binaries. It is a local source artefact, not a published release.

The local 220-file protected tool manifest hashes to `3f9834599d030a8af18e5d926dd2de07dd04394109681103414500c9adabf794`. Entry point `wix.exe` hashes to `cfdba41d6cd13282cee4ad61e9f7f5695ae2c4360f165c69457c1e08b1782bed`, managed `wix.dll` to `b76cded3ad02af63f59be6cdf786766235a1e516d673ad41df273fe2dd759418`, native processing helper to `c0ae4034a15d3edff64343fc67ccd3a347f8eeaadb84b024b57e56e1de3eaa3a`, and Core assembly to `154852d453ba41930983c6afdd4615963ec86f2f9be6f2ecb3b4216f08fc6e40`. These identify the observed local outputs; another source build needs its own delivered-byte manifest. Embedded debug paths and native PE/PDB timestamps prevent a bit-identical rebuild claim.

Source preparation generates version inputs from the exact Git tag, uses the disclosed SDK selector 10.0.403 and compiles source packages in dependency order: base build-task sources, x64 DUtil, Versioning, Data, Extensibility, native MSI processing and the MSI-only CLI. Native compilation uses installed VS MSBuild; managed compilation uses the isolated SDK, explicit x64 and net8.0 CLI targets with the private 10.0.14 runtime. First-party package source mapping points only at locally compiled artefacts; the isolated NuGet configuration clears machine fallback folders. Signing and acceptance properties stay empty. Global cache-cleaning upstream batch helpers are not run. The complete local build recipes, lock and signature evidence accompany the retained source/tool artefacts; CI automation of that source build remains release-pipeline work.

The private tool contains the CLI, required managed libraries, source-built native helper and runtime `host/` and `shared/` trees. It has no SDK, compiler, source tree, package cache or `mergemod.dll`. Product packaging sets `DOTNET_ROOT` and `DOTNET_ROOT_X64` to that private runtime and disables multilevel lookup. Only fixed MSI build, validation and decompilation commands are used; no extension installation or acceptance command is allowed. The [spike record](../../docs/packaging-spike.md) records product outcomes and remaining limits.
